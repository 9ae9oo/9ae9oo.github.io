# Creator Workspace

웹툰·만화 창작자를 위한 통합 브라우저 작업 도구. 작업 관리, 일정, 정산과 세무 참고자료를
브라우저 탭 하나에 모았습니다. 뽀모도로·메모·할 일은 어느 화면에서든 띄우는 플로팅 위젯입니다.

기획서: [`docs/prd-v1.html`](docs/prd-v1.html) (최신) · [`docs/spec-v2.0.html`](docs/spec-v2.0.html) ·
4주 학습 계획: [`docs/pomo_todo_4week_plan.html`](docs/pomo_todo_4week_plan.html)

---

## 바로 써보기

**로컬** — `index.html` 을 더블클릭하면 끝입니다. 설치도, 서버도 필요 없습니다.
(ES module 대신 일반 `<script>` 를 쓰기 때문에 `file://` 에서도 그대로 동작합니다.)

**로컬 서버로 보고 싶다면**

```bash
python3 -m http.server 8000
# http://localhost:8000
```

## 정적 호스팅에 올리기 (FTP / GitHub Pages)

빌드 과정이 없습니다. **저장소 파일을 그대로 올리면 됩니다.**

- **FTP (닷홈 · 아이비 등)** — `index.html`, `css/`, `js/`, `assets/` 를 웹 루트(보통 `public_html/`)에
  통째로 업로드하세요. 모든 경로가 상대경로라서 `example.com/` 이든 `example.com/pomo/` 든 잘 열립니다.
  `docs/`, `legacy/`, `scripts/`, `dist/` 는 앱 동작에 필요 없으니 올리지 않아도 됩니다.
- **GitHub Pages** — 저장소 Settings → Pages → 브랜치를 고르고 폴더는 `/ (root)` 로 두면 됩니다.
- **파일 하나로 옮기고 싶다면** — 아래 단일 파일 빌드를 쓰세요.

```bash
python3 scripts/build-single.py           # dist/mini-workspace.html (CSS·JS·알람소리까지 한 파일)
python3 scripts/build-single.py --fonts   # Pretendard 까지 넣어 완전 오프라인용으로
```

## 설계 원칙

- **단일 원본** — 투두·해빗·거래는 저장소에 한 벌만 존재하고, 화면마다 필터해서 보여줍니다.
  캘린더에서 체크하든 플로팅 창에서 체크하든 같은 데이터가 갱신됩니다.
- **재생과 편집 분리** — 자주 쓰는 조작(재생·입력)은 위젯에서, 가끔 쓰는 관리(재생목록·카테고리)는 설정 페이지에서.
- **반응형 전환** — PC는 상단 네비 + 여러 플로팅 창, 모바일(≤900px)은 하단 탭바 + 전체화면 시트 하나씩.
- **자주 쓰는 것은 상단에** — 뽀모도로·메모·할 일은 어느 페이지에서든 상단 버튼으로 띄웁니다.
  뽀모도로는 창을 닫아도 상단바에 남은 시간이 계속 보입니다.
- **저장은 자동, 저장됐다는 사실은 보이게** — 값이 바뀌면 바로 저장하고 하단에 짧게 알립니다.
- **파생값은 저장하지 않음** — 통장 잔액, 예산 대비 실적, 원천징수액·실지급액은 매번 계산합니다.
- **한 번 입력하고 여러 화면에서 재사용** — 어시 지급을 한 번 적으면 가계부 거래·원천세 집계·
  종합소득세 참고자료가 모두 거기서 파생됩니다. 같은 금액을 두 번 적지 않습니다.
- **개인정보는 최소한만** — 어시스턴트는 이름·작업 정보·지급 자료만 저장합니다.
  주민등록번호·계좌번호·은행 정보는 **입력란 자체를 만들지 않아** JSON 백업에도 남지 않습니다.
- **세무는 참고값** — 이 프로그램은 신고를 대신하지 않고, 세율 적용 여부나 신고 의무를 판단하지 않습니다.

## 데이터

모든 데이터는 이 브라우저의 **LocalStorage(`mw.v1`)** 에만 저장됩니다. 서버로 나가는 데이터는 없습니다.
브라우저 데이터를 지우면 함께 사라지니, **설정 → 일반·데이터 → JSON 내보내기**로 가끔 백업해 두세요.
같은 화면에서 불러오기로 복구합니다.

## 테마 바꾸기

**설정 → 테마**에서 다크/라이트 모드와 강조 색상(버튼·활성 탭 등)을 바로 바꿀 수 있습니다.
색상표에서 골라도 되고 색상 피커로 직접 골라도 됩니다. 이 브라우저에만 저장되며, [기본값으로]로 언제든 되돌립니다.

## 알아둘 제약

| 항목 | 내용 |
|---|---|
| 음악 재생 | YouTube IFrame API 를 불러올 수 있는 네트워크가 필요합니다. 차단되면 상단바가 그 사실을 알려주고 나머지 기능은 정상 동작합니다. |
| 곡 제목 | oEmbed 조회가 CORS 로 막히면, 실제로 재생될 때 제목이 자동으로 채워집니다. 직접 고쳐도 됩니다. |
| iCal 연동 | 구글 캘린더 iCal 주소는 브라우저에서 직접 받으면 CORS 로 막히는 경우가 많습니다. **`.ics` 파일 가져오기**를 권장합니다 (읽기 전용). |
| 알림 | 브라우저 데스크톱 알림이라 **탭이 열려 있는 동안만** 울립니다. 닫아둔 사이 지나간 해빗 알람은 다음에 열 때 "지난 알람"으로 모아 보여주고, 각각 체크하거나 패스할 수 있습니다. |
| 자동 실행 · 트레이 | 브라우저 웹앱은 스스로 켜지거나 트레이에 남을 수 없습니다. 아래 로드맵의 데스크톱 래퍼 단계에서 제공할 예정입니다. |
| 반복 일정 | 전체 일괄 수정·삭제만 지원합니다 (특정 회차 예외 처리 없음 — 기획서 결정 사항). |
| 세무 화면 | 원천세·부가세·종합소득세 숫자는 모두 **참고값**입니다. 실제 신고 전에는 홈택스나 세무사를 통해 확인하세요. |
| 원천징수율 | 지급 건마다 직접 입력합니다(기본 3.3 = 소득세 3 + 지방세 0.3). 프로그램이 "3.3%를 적용해야 한다"고 판단하지 않습니다. |
| 내가 원천징수당한 세액 | 지급처가 내 수입에서 떼어간 세액은 이 프로그램에 들어오지 않습니다. 신고 시 지급명세서를 함께 확인하세요. |
| 공정 순서 드래그 | 마우스 드래그는 데스크톱에서만 동작합니다. 터치 기기는 ↑ ↓ 버튼을 쓰세요. |

## 해빗 트래커 쓰는 법

1. **설정 → 시간 · 해빗**에서 해빗을 만들고 색을 고릅니다.
2. 그 해빗에 **알람 시각을 등록합니다** (최대 12개). 예: 물 6잔이면 09:00 · 11:00 · 13:00 · 15:00 · 17:00 · 19:00.
   **등록한 알람 개수가 그날의 목표 횟수**가 됩니다.
3. 시각이 되면 알림이 뜨고, 화면 오른쪽 아래 카드에서 **[체크]** 또는 **[패스]** 를 고릅니다.
   체크한 만큼 그날 횟수가 쌓입니다.
4. 트래커 칸을 직접 눌러도 +1 됩니다. 다 채운 뒤 한 번 더 누르면 그날 기록이 비워집니다.
5. 알람을 하나도 등록하지 않으면 하루 1회 단순 체크형으로 동작합니다.

칸은 1회 이상 하면 해빗 색으로 칠해지고 안에 횟수가 적힙니다. 목표를 다 채운 날은 테두리로 표시됩니다.
트래커는 **홈**에만 둡니다 (캘린더에도 두면 같은 내용이 반복됩니다).

## 작업 체크보드 쓰는 법

1. **작업** 페이지에서 작품을 만들고, 회차를 추가하며 **전체 컷 수**를 적습니다.
   63컷이면 `1~10 / 11~20 / … / 61~63` 줄이 자동으로 생깁니다.
2. 회차를 만들면 기본 공정 **콘티 · 선화 · 밑색 · 명암 · 후보정** 이 함께 생깁니다.
3. 칸을 **한 번 클릭**하면 체크, 다시 누르면 해제입니다. 줄 왼쪽의 `1~10` 을 누르면 그 줄 전체가 토글됩니다.
4. 공정 이름 왼쪽 화살표로 접고 펼칩니다. 접힘 상태도 저장됩니다 (모바일은 한 번에 하나만 펼칩니다).
5. **[순서 변경]** 을 누르면 그때만 손잡이(⠿)·↑↓·이름 수정(✎)·삭제(✕)가 나타납니다.
   평상시에는 숨겨 두어 화면이 체크에만 집중되게 했습니다.

진행률 퍼센트나 "23/63" 같은 통계는 기획서 결정대로 넣지 않았습니다.

## 정산 쓰는 법

**가계부 → 어시스턴트 → 세무** 순서로 한 번씩만 입력하면 나머지는 파생됩니다.

1. **어시스턴트 → 작업자** 에서 사람을 등록합니다. 여기서 **지급 기준**을 고르는 것이 중요합니다.
   - **세전 기준** — 적은 금액이 총 지급액이고, 원천징수를 뺀 나머지를 보냅니다. (180,000 적으면 174,060 입금)
   - **세후(입금액) 기준** — 적은 금액을 그대로 보내고, 총액은 역산합니다. (174,060 적으면 총액 180,000)
2. **지급 내역** 에서 회차별 지급을 등록합니다. 저장하면 가계부에 `업무 → 어시비` 거래가
   **실제 입금액으로** 자동 생성되고 서로 묶입니다. 그 거래는 지급 기록에서만 고칠 수 있습니다.
3. **세무 → 원천세** 에 지급월별 원천징수액이 모입니다. 실제로 납부한 날 **[납부 기록]** 을 누르면
   `세금 → 소득세` 거래가 만들어져 통장 잔액과 연간 비용이 모두 맞아떨어집니다.
4. 부가세를 쓰려면 거래를 넣을 때 **부가세 구분(과세/면세)** 과 **증빙**을 골라 둡니다.
   세무 → 부가가치세에서 매출·매입으로 나눠 집계하고, 빠뜨린 거래는 "확인이 필요한 거래"로 모아 줍니다.

작업자의 단가나 세율을 나중에 바꿔도 **이미 등록한 지급 기록은 바뀌지 않습니다.**
