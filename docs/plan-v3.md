## 1. 메모장 — 트위터식 개편  〈규모: 큼〉

### 현황
- 오른쪽 도킹 패널. 헤더에 태그 필터 칩, 그 아래 고정 입력줄, 아래로 포스트잇 카드 리스트.
- 본문은 `MW.markdown` 로 렌더( `**볼드**` 등 기호 직접 입력 ).
- 분류 = `store.memoTags` 그룹(카드마다 태그 드롭다운, 태그 색 = 카드 색).

### 목표
"작성 → 타임라인 → 검색" 이 있는 미니 트위터. **제목 없음.**

```
            📝  (메모 아이콘, 중앙)
────────────────────────────────────
[ 내용 입력 …  본문에 #해시태그 로 분류 ]

 B  I  S  ☑  🖊              [ 기록 ]     ← 서식 버튼은 입력창에만
════════════════════════════════════
🔍 [ 검색 — 내용·#해시태그 ]
════════════════════════════════════
♡   ·  2시간 전                🔒  🗑
내용 본문 …  #아이디어 #웹
(길면 5줄에서 접고 "더보기")
────────────────────────────────────
♡   ·  어제
…
```

### 변경 내용
- **상단 작성 박스** = 지금의 고정 입력줄을 확장: 내용(`contentEditable`) + 서식 버튼 + `[기록]`.
  - **제목 필드 없음.** 위쪽에 메모장 아이콘만.
- **서식 = 실제 서식 (마크다운 아님)**, 그리고 **빠르게**:
  - `contentEditable` 편집 영역에서 **네이티브 단축키** `Ctrl/⌘ + B / I / U` 가 바로 먹음 → 텍스트 선택 후 Ctrl+B 로 즉시 굵게. (기호 `**` 안 씀.)
  - 마우스·모바일용으로 입력창에 작은 서식 바: 굵게 · 기울임 · 취소선 · 밑줄 · 형광펜 · 체크박스.
  - 저장: 정제된 HTML (허용 태그 `b i s u mark br` + 체크리스트용 최소 구조만). 렌더 시 화이트리스트로 재정제.
  - `MW.markdown` 은 메모에서 안 씀(메모 외 다른 곳 사용처는 유지).
- **분류·검색 (둘 다 유지)** — 메모가 늘어도 찾게:
  - **해시태그 필터 바**(헤더): 본문의 `#태그` 를 모아 **사용 빈도순** 가로 스크롤. `전체` · `미분류` 포함. 카드 본문의 `#태그` 클릭도 같은 필터.
  - **검색창**: 본문·태그 부분 일치. 활성 태그 필터와 **AND**.
  - **북마크(♡) 필터**: 켜면 북마크한 것만.
  - (선택) 정렬: 최신 / 오래된 / 최근 수정.
- **카드**
  - 윗줄: `♡ 북마크` · `상대 날짜(작성일)` — 왼쪽 / `🔒 잠금` · `🗑 삭제` — 오른쪽(평소 흐리게, hover 시 진하게)
  - 본문: 서식 적용된 모습. 길면 ~5줄에서 접고 "더보기".
  - 편집: 카드 우상단 `✎`(또는 본문 클릭) → **그 자리에서** `contentEditable` 편집 + 서식 바 노출.
    포커스 아웃 = 저장, `Esc` = 취소(되돌리기). 위쪽 `🔒 🗑` 와 같은 줄, 평소 흐리게/hover 진하게(모바일은 항상).
  - **에디터는 상단 작성 박스와 같은 컴포넌트 하나를 재사용** — 상단 = 새 메모, 인라인 = 기존 메모 수정. (상단으로 불러오는 방식은 스크롤·초안 충돌 때문에 안 씀.)
- **잠금(🔒)**: 켜면 🗑 비활성 → 해제해야 삭제(실수 방지).
- **북마크(♡)**: 토글. "북마크만" 필터로 사용.

### 데이터 모델 (`store.js` `memos[]`)
```
{ id, body, createdAt, updatedAt, locked:false, bookmarked:false }
```
- `title` · `groupId` · `color` 제거. `memoTags` 배열 제거(해시태그를 본문에서 자동 수집).
- 마이그레이션: 기존 메모 → `createdAt = updatedAt = Date.now()`, `locked/bookmarked = false`.
  기존 `title` 은 본문 맨 앞 굵은 줄로 합침(`<b>제목</b><br>` + body). 기존 `body` 의 `**/*/~~` 는 1회 HTML 변환.
- `VERSION` 올릴지는 구현 시 판단(현재 migrate 는 매 로드 실행).

### 결정 사항 (모두 정해짐)
- **제목 없음.** 카드 위쪽은 `♡ · 날짜`, 분류는 본문 `#해시태그` 하나로 통일.
- **해시태그 색** — 자동색 없음. `#태그` 칩·형광펜·강조는 **테마 포인트 컬러 `var(--accent)`**. 카드는 무채색.
- **분류 UI** — 해시태그 필터 바 + 검색창 + 북마크 필터 셋 다.
- **서식 저장** — (A) `contentEditable` + 정제 HTML. 입력은 네이티브 단축키 + 작은 서식 바.
- **형광펜/밑줄** — `<mark>` / `<u>`. `document.execCommand` 사용.
- **체크박스** — **토글 가능**: 읽기 상태에서 체크박스를 눌러도 ☐↔☑ 바뀌고 저장됨(메모를 살아있는 할일 목록처럼). 편집으로 안 들어가도 됨.

## 2. 메뉴 애니메이션 줄이기  〈규모: 작음〉

- 설정 → 테마(또는 일반)에 **"동작 줄이기"** 토글.
- 켜면 `html.reduce-motion` → CSS 로 `.side-panel` transition, 플로팅 창 애니메이션, `.tab`/route 전환 등 `transition`·`animation` 을 `0s` 로.
- 기본값은 OS 설정(`@media (prefers-reduced-motion: reduce)`) 을 따르고, 토글은 그 위에 덮어쓰기(강제 ON / 강제 OFF / 자동).
- 저장: `settings.reduceMotion` (`'auto' | 'on' | 'off'`).

## 4. 작업 페이지 정리  〈규모: 중〉

### 현황 (`js/work.js`)
- `.work-toolbar`: [작품 select] [✎] [＋ 작품] … **[순서 변경]** (오른쪽)
- `.ep-bar`: 회차 칩 `[1화 60컷][2화 …][＋ 회차]`
- `.ep-head`: `[N화 · 부제]  [전체 60컷]  …  [회차 설정]`  ← "회차 설정" 은 모달(번호·컷수·부제·삭제)
- `.board`: 공정 노드. `.proc-head` = `[▾ 공정명]` (순서 변경 모드에서만 `⠿ ↑ ↓ ✎ ✕`)

### 변경 내용
- **4a. 회차 칩 → 브라우저 탭 모양** — `.ep-chip` 를 크롬 탭처럼(윗모서리 둥근/사다리꼴, 활성 탭이 아래 보드와 이어져 보이게). 기능(선택·`＋`)은 그대로, **CSS 위주**.
- **4b. "전체 nn컷" 인라인 편집** — `.ep-head` 의 `전체 60컷` 옆에 `✎`. 누르면 `전체 [ 60 ] 컷` 숫자 입력으로 바뀌고 Enter/blur 시 저장. (컷 수 줄이면 사라진 컷 체크 정리 — 기존 `episodeDialog` 로직 재사용.)
- **4c. "순서 변경" 위치 이동** — `.work-toolbar` 오른쪽 → 공정 보드 근처(`.ep-head` 오른쪽, 기존 "회차 설정" 자리). 공정 순서를 바꾸는 기능이므로 공정 목록 옆이 맞음.
- **4d. "회차 설정" 모달 정리** — 컷수는 4b 인라인으로 빠졌으니, 남는 것은 회차 번호·부제·삭제. 작은 `⚙`(또는 탭 우클릭/롱프레스)로 접근. 라벨도 "회차 정보" 등으로.
- **4e. 공정별 "남은 컷수"** — `.proc-head` 에 `남은 N컷` 배지 = `ep.cutCount − pr.completedCuts.length`. 0 이면 "완료" 표시.

### 데이터 영향
- 없음. 화면/조작 위치만 바뀜(`works[]` 스키마 그대로).

## 6. 셸 레이아웃 전면 개편  〈규모: 큼〉

> UI 가 복잡하다는 판단. 도구(메모·음악·뽀모도로)가 3군데 흩어진 것을 **오른쪽 레일 하나로**
> 모으고, PC/모바일 레이아웃을 확실히 가른다. #5 의 사이드바 배치를 다시 조정한다.

### 현재 구조
`#app`(flex row) = `#sidebar`(좌측 아이콘 레일: 홈·작업·캘린더·정산·뽀모도로 / footer: 설정) + `#body`(column).
`#body` = `#topbar`(음악바만) + `#main`(`.page`×5) + `#tabbar`(빠른 입력). 메모 = `.side-panel`(오른쪽 도크).
뽀모도로 = `registerFloat`.

### PC — "시안 A" (모바일 분기점 위의 모든 폭. 창이 3000px 든 1000px 든 동일 규칙)

```
닫힘:  [좌측레일] [ 메인 컨텐츠 (max-width) ] [·······여백(배경)·······] [탭] │화면끝
열림:  [좌측레일] [ 메인 컨텐츠 (줄어듦) ] [·여백·] [탭][  패널  ] │화면끝
```

**우측 레일(탭) = "패널 존"의 왼쪽 가장자리에 붙어 다니는 인덱스 탭.** 화면에도 컨텐츠에도
고정 안 됨. 패널과 항상 한 몸.

- **패널 존** = 화면 오른쪽 끝에 붙은 폭 `--side-panel-w` 영역. **닫히면 0, 열리면 `--side-panel-w`.**
  - 닫힘 → 존 왼쪽 = 화면 오른쪽 끝 → **탭이 화면 오른쪽 가장자리**에. 컨텐츠와 탭 사이는 배경 여백.
  - 열림 → 존 왼쪽 = `100vw − 패널폭` → **탭이 패널 왼쪽 가장자리에 딱 붙음.** 패널은 화면 끝까지 채움
    (위·아래·오른쪽 여백 0).
- **창 리사이즈**: 패널·탭은 항상 **화면 오른쪽 끝 기준 고정** (열린 상태면 탭의 화면 x 는 불변).
  변하는 건 왼쪽 메인 컨텐츠 폭뿐.
- **메인 컨텐츠**: `flex: 0 1 var(--content-max)` + `margin-right: auto`.
  - 여유 공간은 **컨텐츠(max) 채운 뒤 남는 걸 `margin-right:auto` 가 흡수** → 탭·패널을 화면 오른쪽 끝으로 밈.
  - 패널 열리면 **여백(auto)이 먼저 줄고**, 그래도 모자라면 컨텐츠가 줄어듦(flex-shrink).
    → 3000px 창: 컨텐츠 max 유지, 가운데 여백만 축소. 1000px 창: 컨텐츠가 실제로 줄어듦.
- **구현**: `#panelhost` = 오른쪽 끝의 flex 스페이서(`flex-basis` 0→`--side-panel-w`, `overflow:hidden`,
  `position:relative`). `.side-panel` 은 `#panelhost` 안에 `position:absolute; right:0; width:--side-panel-w`.
  host 가 넓어지며 드러남(왼쪽으로 wipe = 슬라이드). `#toolrail` 은 `#content` 와 `#panelhost` 사이 flex 항목
  → 자동으로 host(패널) 왼쪽에 붙음. `#app { justify-content: flex-start; padding-right: 0 }`.
- **좌측 레일**: 홈·작업·캘린더·정산·**설정** (아이콘만, 세로 가운데 작은 메뉴, footer 분리 없음).
- **우측 레일 탭**: `메모장` · `BGM` · `뽀모도로` (세로 텍스트, 개별 작은 라운드 박스, 바깥쪽만 둥글게).
  메모장·BGM → `registerPanel` 패널. 뽀모도로 → 플로팅 창 토글(크기 조절 유지, z-index 최상위).
- **입력창**(빠른 일정): 컨텐츠 하단 가운데 **떠 있음**. 바 배경 없음, 테두리 2px, ≈46px.
- **상단바(`#topbar`) 제거** — 음악은 BGM 패널로.
- **패널끼리 전환**(메모장 ↔ BGM)은 슬라이드 없이 즉시(`body.panel-instant`).

### 모바일 (`< 640px`, 값은 한 곳에서 조정 — 사용자 테스트 후 확정)

```
┌─────────────────────────┐
│ 홈·작업·캘린더·정산·설정  │ ← 상단 nav 바 (가로, 필요시 스크롤)
├─────────────────────────┤
│      메인 컨텐츠          │
│                         │
│    [메모장·음악·뽀모]     │ ← 떠 있는 도구 pill (컨텐츠 위, 하단쯤)
│    [   일정 입력창   ]    │ ← 떠 있는 입력창 (그 아래)
└─────────────────────────┘
```

- 좌·우 레일 없음. 도구 탭을 누르면 **아래에서 패널이 올라와 화면 대부분을 덮음**,
  상단에 `×` 또는 `▼ 접기` 버튼. (메모/음악/타이머 각각)
- 입력창은 안전영역(`env(safe-area-inset-bottom)`) 위에.

### 새 테마 설정 — 컨텐츠 폭

- `settings.theme.contentWidth`: `'narrow'(880) | 'normal'(1040) | 'wide'(1240) | 'full'(제한없음)`. 기본 `'normal'`.
- `applyTheme()` 이 `--content-max` 를 `<html>` 에 인라인으로. 설정 → 테마에 세그먼트 컨트롤 추가.
- migrate: 값 검증(잘못되면 `'normal'`).

## 8. 대시보드 위젯 2차 — 종류 확장 + 4칸 그리드 + 행 높이 설정  〈규모: 큼 · 상태: 결정 사항 모두 정해짐〉

> 커밋 `01c0965` 로 편집 모드 + `homeWidgets` 위젯 시스템은 이미 들어갔다. 이번은 그 위에
> **위젯 종류를 늘리고, 그리드를 4칸으로, 행 높이를 유저가 고르게** 하는 확장.

### 현황 (`js/app.js`)
- 3칸 그리드, 세로 최대 3칸. 행 높이는 내용에 따라 자동(`HOME_ROW_UNIT=140` 은 드래그 환산용).
- 편집 모드: 임시본 `draft` 에서 작업 → `저장` 눌러야 반영, `취소` 가능.
- `settings.homeWidgets: [{ id, type, enabled, config }]` + `WIDGET_DEFS` 레지스트리 + `ADDABLE_TYPES`.
- 고정(토글만): 오늘 일정 · 내일·미뤄진 일정 · 해빗 · 가계부.
- 추가·삭제 가능(여러 개): 이미지 갤러리 · 미니 달력 · HTML 임베드.
- 위젯별: 가로 span(1~3) · 세로 rowSpan(1~3) · 자유 픽셀 높이.

### 변경 내용

- **8a. 그리드 4칸 + 행 높이를 유저가 설정**
  - `HOME_COLS` 3 → 4, `HOME_ROWS_MAX` 3 → 4 (`4:4` 까지).
  - 행 높이 = 내용 자동 대신 **고정값을 유저가 고름**. `settings.theme.dashRowHeight`:
    `low / normal / high` (px 는 구현 시 확정, 예 84 / 112 / 140). 기본 `normal`.
  - `applyTheme()` 이 `--dash-row` 를 `<html>` 인라인으로. 설정 → 테마에 **컨텐츠 폭과 나란히** 세그먼트 컨트롤.
  - 칸 너비는 컨텐츠 폭 ÷ 4 로 자동(별도 설정 없음).
  - migrate: 값 검증(잘못되면 `normal`).
  - 주의: `normal` 컨텐츠 폭(~1040)에서 한 칸 ≈ 240px. 1×1 메모는 작은 스티커 수준 —
    너무 좁게 느껴지면 기본 칸 수 3 유지도 검토.
  - 유동(뷰포트에 맞춰 행 높이 자동)은 **안 씀**: 대시보드는 세로로 넘쳐서 스크롤이 생기고,
    `grid-auto-rows:1fr` 를 쓰려면 그리드 높이를 고정해야 하는데 그러면 화면 크기마다 위젯이
    못 읽을 만큼 납작해지거나 부풀고 스크롤과 싸운다.

- **8b. 타이머 위젯 4종 (각 1×1, 2×1 허용)**
  - `ADDABLE_TYPES` 에 `timer-pomodoro` · `timer-countdown` · `timer-stopwatch` · `timer-alarm`.
    **모드 드롭다운이 아니라 종류가 곧 선택** — 넷의 화면·동작이 완전히 다름(링 / 시간 입력칸 / 랩 / 시계).
  - `js/timer.js` 의 **하나뿐인 실행 상태를 공유·조종**. 위젯에서 시작 → 뽀모도로 플로팅 창에도 반영,
    타이머 위젯이 여러 개면 같은 상태를 비춤. (알람시계는 원래 나머지 셋과 독립.)
  - `timer.js` 를 위젯에서 mount 할 수 있게 각 모드 렌더를 패널 전용에서 분리해야 함.

- **8c. 메모 위젯 1종 + 모드 설정 (1×1 ~ 3×3)**
  - `type: 'memo'`, `config.mode`: `단일`(핀 고정한 메모 1개) / `리스트`(전체 타임라인) /
    `태그`(본문 `#해시태그` 필터 결과). `config = { mode, memoId?, tag? }`.
  - 세 형태가 *같은 데이터(메모 목록)를 다르게 보여주는 것*이라 모드로 묶음. 크기만 키우면
    스티커(1×1) ↔ 타임라인(3×3) 으로 자연스럽게 읽힘.
  - 여러 개 추가 가능 — 태그별 메모 위젯 여러 장.
  - `js/memo.js` 의 카드 리스트 렌더를 위젯에서 호출할 수 있게 재사용.

- **8d. 주간 일정 위젯 (2×1 / 3×1)**
  - 7일 가로 스트립. **일정 + 날짜 있는 할 일** 합쳐 표시(`js/calendar.js` `eventsOn` + `todosOn` 재사용).
  - 완료된 할 일은 흐리게(숨김 아님 — 구현 때 확인).
  - `config`: 이번 주 고정 / 주 offset.

- **8e. 미니 달력 (1×1) — 이미 있음, 역할만 정리**
  - 날짜 + 일정 있는 날 **점만**. 클릭 시 캘린더 이동. (칸 안 텍스트는 8f 월간이 담당.)
  - 날짜 있는 할 일도 점에 포함.

- **8f. 월간 일정 위젯 (2×2 / 3×3)**
  - 캘린더 페이지 월간 뷰를 임베드. 칸 안에 일정 **텍스트까지**. 일정 + 날짜 있는 할 일.
  - `js/calendar.js` `renderMonth` 를 페이지 밖에서 mount 가능하게.

- **8g. 타임 블럭 위젯 (2×1 / 3×1) — 일간을 축소**
  - **새 데이터 모델 없음.** 일정의 `start`/`end`(분) + `allDay`, 기존 일간 뷰(`renderDay`) 재사용.
  - 시간 레일 + 오늘의 시간 있는 일정을 블록으로. 하루종일·마감 할 일은 위쪽 띠.
  - v1 **읽기 전용**(탭 → 캘린더 일간 열기). 드래그로 블록 만들기·옮기기는 별도 기능.
  - 2×1/3×1 은 24시간 담기엔 짧음 → **지금 시각 주변 창**(예: −1h ~ +5h)만 보이고 나머지는 스크롤.

- **8h. "내일" / "미뤄진 일정" 분리 (각 1×1)**
  - 현재 고정 위젯 `next`(`내일 · 미뤄진 일정` 한 장, `nextCard`)를 `tomorrow` + `postponed` 두
    고정 위젯으로 분리. 둘 다 `builtin:true` 토글.
  - migrate: 기존 `next` 의 enabled·순서 자리를 둘에 물려줌.

### 편집 UX

- 현재 편집 모드 흐름 유지(편집 → `draft` → 저장/취소).
- 위젯별 **⚙ 설정** 추가: 편집 모드에서 카드에 `⚙` → 작은 팝오버 = 위젯별 설정
  (메모 모드+대상, 주간/월간 주·달, 타임블럭 시간창) + **크기 프리셋 선택**(그 위젯 허용 크기만).
  타이머 4종은 설정할 게 크기뿐.
- "＋ 위젯" 은 항상 **새 인스턴스** — 같은 메모/타이머 위젯 여러 개 가능.
- 팔레트가 길어지므로 `editToolbar` 의 add 버튼을 분류(일정 / 메모 / 타이머 / 기타)해서 정리.

### 데이터 모델 (`store.js`)

- `settings.homeWidgets[]` 의 `config` 확장: 타이머(없음), 메모 `{mode, memoId?, tag?}`,
  주간 `{weekOffset?}`, 월간 `{monthOffset?}`, 타임블럭 `{windowBefore?, windowAfter?}`.
- `settings.theme.dashRowHeight`: `'low' | 'normal' | 'high'`, 기본 `'normal'`.

### 영향 파일

`js/app.js`(위젯 레지스트리·렌더·편집 팔레트·⚙ 팝오버), `js/store.js`(스키마·migrate·`VERSION`),
