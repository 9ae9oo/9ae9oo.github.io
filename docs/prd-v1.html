PRODUCT REQUIREMENTS DOCUMENT · V1

개인 창작자용 WorkSpace

웹툰/만화 창작자의 작업 관리, 일정, 정산 및 세무 신고 참고자료를 한곳에서 정리하는 개인용 HTML 프로그램.

본 프로그램은 세무 신고를 대신하는 프로그램이 아니라, 신고 시 참고할 자료를 정리·집계하는 것을 목적으로 한다.

1. 제품의 핵심 방향

작업작품 → 회차 → 컷 → 공정 단위로 제작 진행을 체크한다.
정산가계부와 어시스턴트 지급을 실제 거래/지급 데이터 중심으로 관리한다.
세무 참고원천세·부가세·종합소득세 신고에 필요한 자료를 자동 집계해 확인한다.
설계 원칙
세무 기능은 신고 행위를 대신하지 않는다. 사용자가 실제 신고 전에 자료를 검토하고 세무 전문가 또는 국세청 안내와 대조할 수 있는 참고용 자료 관리 기능으로 제한한다.

5. 작업 관리 — 핵심 기능

기존 Google Sheets에서 사용하던 컷별 공정 체크 방식을 더 단순하고 읽기 쉬운 체크보드로 재구성한다.

작품

         │    ├── 1컷 완료 여부

         ├── 공정 2

5-2. 작품 / 회차

  • 작품 이름을 사용자가 추가한다.
  • 작품 안에 회차를 추가한다.
  • 각 회차마다 전체 컷 수를 입력한다.
  • 예: 63컷이면 자동으로 1~10 / 11~20 / ... / 61~63 행을 생성한다.
  • 컷 수는 10단위로 고정하지 않는다.

9. 원천세

원천세는 어시스턴트 지급 데이터에서 자동으로 집계하는 것을 기본 방향으로 한다.

신고용 총 지급액
        ↓
사업소득세 3%
        ↓
지방소득세 0.3% (3% 국세의 10%라는 구조)
        ↓
원천징수 합계
        ↓
실제 지급액
필드목적
년도귀속연도/조회 기준
작업자 이름지급 대상 확인
작업 내역지급 근거 메모
고정 지급금회차당 지급액 × 회차수
추가 지급금추가 작업/컷 등에 따른 금액
실제 지급액원천징수 후 지급액
신고용 총 지급액원천징수 전 금액
원천징수 합계소득세 + 지방소득세
사업소득세기본 3% 표시
지방세기본 0.3% 표시
입금 정산일실제 지급일
세금 신고일신고 완료일 기록
세무 주의: 프로그램은 3.3%를 모든 지급에 무조건 적용하는 법적 판단을 하지 않는다. 국세청 기준상 원천징수 대상 사업소득에는 3% 원천징수가 안내되지만, 실제 적용 여부와 지급 유형은 확인이 필요하다. 지방소득세와 신고·제출 의무도 최신 국세청 기준을 확인한다.

10. 부가가치세

부가가치세는 가계부의 거래 데이터를 활용하되, 별도의 세무 화면에서 집계한다.

가계부 거래
  ├── 과세 매출 → 매출세액
  ├── 과세 매입 → 매입세액
  ├── 면세/비과세 등
  └── 증빙 정보
          ↓
      부가세 참고자료
          ↓
    매출세액 - 매입세액

국세청은 일반과세자의 부가가치세 계산에서 매출세액과 매입세액을 구분하고, 그 차이를 납부(환급)세액 계산에 사용한다. 따라서 UI도 매출과 매입을 분리해서 보여주는 방향으로 설계한다.

11. 종합소득세

종합소득세는 특정 거래를 입력하는 장부라기보다, 여러 데이터에서 신고 참고자료를 모아 확인하는 최종 집계 화면으로 설계한다.

가계부 수입/지출 ───────┐
                        ├──→ 종합소득세 참고자료
어시스턴트 지급 ────────┤
                        │
원천징수 자료 ──────────┘
  • 사업 수입
  • 사업 관련 지출/필요경비 참고자료
  • 어시스턴트 지급 및 인건비 관련 자료
  • 원천징수된 세액 참고자료
  • 연도별 집계

실제 종합소득세 계산·신고의 세부 요건은 사업자 유형과 소득 종류 등에 따라 달라질 수 있으므로, V1에서는 “신고 참고자료”에 초점을 둔다.

12. 데이터 저장 / 개인정보 원칙

저장 방식

  • HTML/CSS/JavaScript 기반의 개인용 프로그램
  • 데이터는 JSON 형태로 백업할 수 있도록 설계
  • GitHub 또는 개인 호스팅 환경에서 배포/사용 가능하도록 고려
  • 데이터 구조는 UI와 분리하여 추후 저장방식 변경이 가능하도록 설계

개인정보 최소화

어시스턴트 개인정보 최소화 원칙
이름·작업정보·지급 관련 자료만 관리한다. 주민등록번호는 수집하지 않으며, 계좌번호와 은행 정보도 저장하지 않는다.
  • 주민등록번호 입력 필드 자체를 만들지 않는다.
  • 계좌번호 입력 필드 자체를 만들지 않는다.
  • JSON 백업에도 해당 정보가 존재하지 않도록 데이터 모델에서 제외한다.
  • 향후 인증/공유 기능이 추가될 경우 JSON 백업의 개인정보 노출 위험을 별도로 검토한다.

15. 개발 시 지켜야 할 UX 원칙

  1. 체크는 한 번의 클릭으로 끝난다.
  2. 사용자에게 필요하지 않은 숫자와 통계를 보여주지 않는다.
  3. 입력 데이터는 한 번만 입력하고 필요한 화면에서 재사용한다.
  4. 설정 변경 후 저장 상태를 명확하게 알려준다.
  5. 세무 계산 결과는 “신고 확정값”이 아니라 “참고값”으로 표현한다.
  6. 공정의 순서는 사용자가 결정한다.
  7. 작업 관리 화면은 기존 스프레드시트보다 단순해야 한다.
  8. 기능을 추가하기 전에 실제 사용 빈도와 필요성을 검증한다.

16. V1에서 하지 않는 것

  • 실제 세무 신고 제출 자동화
  • 주민등록번호 수집
  • 계좌번호/은행 정보 저장
  • 세무 전문가 수준의 법적 판단
  • 과도한 생산성 통계
  • 복잡한 프로젝트 관리 기능
  • 작업시간 강제 기록

17. 참고 근거 — 국세청

세무 관련 기능은 구현 시 아래 공식 국세청 안내를 기준으로 최신 내용을 확인한다.

  • 국세청 — 사업소득 원천징수방법 : 원천징수 대상 사업소득의 원천징수 방법 및 납부 관련 안내.
  • 국세청 — 부가가치세/소득세 : 매출세액·매입세액 및 납부(환급)세액 구조.
  • 국세청 — 종합소득세 개요 : 종합소득세 관련 기본 안내.
  • 국세청 — 소득금액 계산 : 장부 기록 사업자의 총수입금액과 필요경비를 통한 소득금액 계산 안내.
문서 성격: 1인 개발자 전달용 제품 기획서 초안 · V1
본 문서는 실제 세무 신고를 위한 법률/세무 자문서가 아니며, 세무 기능 구현 시 최신 국세청 및 관련 법령을 별도로 확인해야 한다.
