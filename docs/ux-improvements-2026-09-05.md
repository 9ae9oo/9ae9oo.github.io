# UX 개선 — 2026-09-05 사용자 피드백

## 확정한 기준

- Inbox = 날짜·시간이 없는 할 일 목록. Calendar = 일정이 있는 할 일 목록.
- `내일 원고 마무리`는 내일의 종일 일정이다. 할 일/일정 수동 전환은 추가하지 않는다.
- 빠른 입력은 사용자가 쓴 내용을 정리하여 목적지, 날짜, 시간, 내용을 저장 전에 보여준다.
- 메뉴 이름은 Dashboard / Workflow / Calendar / Money / Settings로 통일한다.
- 현재 메뉴 배치를 유지하고 아이콘 아래에 작은 이름을 붙인다.

## 이번 적용 범위

| 항목 | 동작 |
|---|---|
| 빠른 입력 미리보기 | 날짜 없는 글은 Inbox, 날짜·시간이 있으면 Calendar로 안내. 날짜만 있으면 종일, 시간만 있으면 오늘, 기본 종료 시각은 시작 1시간 뒤(자정까지). Enter 또는 저장 버튼으로 확정한다. |
| 입력 오류 | 없는 날짜, 범위를 벗어난 시간, 날짜·시간만 입력한 경우는 정리 화면에서 수정 안내. 한글 조합 중 Enter로 중복 저장하지 않는다. |
| Inbox 완료 목록 | 진행 중/완료 개수와 목록을 표시한다. 날짜 없는 완료 항목만 포함하고, 체크를 해제하면 진행 중으로 돌아온다. 카테고리 필터는 양쪽에 동일하게 적용한다. |
| 메모 저장 표시 | 패널 안에서 저장 중/이 브라우저에 저장됨·시각/저장 실패를 구별한다. 실제 저장 성공 신호 뒤에만 저장됨을 표시한다. 새 메모는 기록 버튼으로 저장한다는 안내도 별도로 둔다. |
| 메뉴 | 아이콘 아래 영어 이름을 표시하고 PLAN 제목을 CALENDAR로 맞춘다. |
| 빈 화면 | 첫 해빗 추가 버튼은 Settings의 해빗 이름 입력칸으로 연결한다. Inbox는 입력창 위치에 의존하는 ‘아래’ 안내를 없애고 입력창으로 가는 버튼을 둔다. |

저장 데이터 형식은 유지한다. 완료 목록은 기존 `todos[].done`을 이용하며, 저장 상태와 미리보기는 백업에 넣지 않는 화면용 정보다.

## 후속 기획 — 아직 구현하지 않음

### Dashboard: 오늘 항목 처리

- 오늘 일정, 미뤄진 항목의 확인에서 완료·날짜 변경까지 이어지는 동선을 대시보드 기획에 포함한다.
- 완료는 명확한 체크 버튼, 날짜 변경은 별도 버튼으로 제공한다. 상태 텍스트에 동작을 숨기지 않는다.
- 미뤄진 항목은 ‘오늘로 옮기기’를 제공하고, 적용 전에 바뀔 날짜를 보여준다.
- 같은 항목을 별도로 복제하지 않고 Calendar의 원본을 갱신한다.
- 현재 `events`에는 완료 속성이 없으므로 Calendar 일정의 완료 표시·저장 구조와 함께 설계한다. 기존 날짜 있는 `todos`만 처리하는 임시 기능으로 끝내지 않는다.
- PC는 행 안의 조작, 모바일은 선택한 항목의 간결한 조작 영역을 검토한다.
- 확인 기준: 완료·날짜 변경 결과가 Calendar와 일치하고 새로고침 후 유지된다. 날짜 변경을 취소하면 원래 일정이 유지된다.

### Workflow: 회차 바로 찾기 / 주변 보기

- 목적: 장기 연재에서도 회차 목록이 보드를 밀어내지 않고 원하는 화에 도착하게 한다.
- ‘회차 이동’에 숫자를 입력하면 현재 작품 안의 해당 회차를 선택한다. 없는 번호라면 ‘해당 회차가 없습니다’를 표시하고 선택을 유지한다. 새 회차를 자동 생성하지 않는다.
- ‘전체 / 주변’은 보기 방식만 바꾼다. 회차 데이터나 기존 번호 그룹 규칙은 변경하지 않는다.
- 주변 보기 제안: 선택 회차를 중심으로 실제 존재하는 앞뒤 2개 회차를 표시한다. 번호가 건너뛰어도 빈 버튼을 만들지 않는다.
- 이전/다음으로 이웃 회차를 선택할 수 있다. 첫·마지막 회차에서는 해당 방향 버튼을 비활성화한다.
- 현재 작품 이름과 선택 회차, 전체 회차 수를 유지하고 ‘전체 보기’로 언제든 돌아간다. 회차 추가 버튼도 숨기지 않는다.
- 작품을 바꾸거나 회차를 삭제하면 유효한 선택으로 갱신한다. 빈 작품에서는 찾기와 주변 보기를 숨긴다.
- 확인 기준: 1화/중간/마지막, 누락된 번호, 100개 이상 회차, 작품 전환, 모바일에서 이동·선택·전체 복귀를 확인한다.
- 세부 배치와 주변 회차 개수는 구현 전 화면 검토에서 확정한다.

### 백업 복구: 교체 범위 미리보기

- 버튼 이름은 ‘백업 파일로 저장 / 백업에서 복구’로 변경하고 JSON은 부가 설명으로 둔다.
- 파일 선택 → 읽기·검증 → 현재/백업 비교 → 현재 데이터 백업 → 교체 실행 순서로 구성한다.
- 비교에는 작품·회차, Inbox 항목(진행/완료), Calendar 일정, 메모, 해빗·기록, 장부·어시스턴트, 설정·재생목록을 포함한다. 실제 스키마 전체를 확인해 빠진 교체 영역이 없게 한다.
- 이번 복구는 ‘전체 교체’임을 명시한다. 개수 차이를 추가/삭제 내역으로 오해하게 표시하지 않는다. 동일 개수라도 내용은 교체된다고 설명한다.
- 미리보기용 마이그레이션은 복사본에만 적용한다. 취소하거나 파일이 잘못됐을 때 현재 데이터와 저장소를 건드리지 않는다.
- 유효한 JSON인지만 확인하지 말고 앱 백업인지, 지원하는 버전·자료형인지도 검증한다. 더 최신의 미지원 백업은 교체하지 않고 안내한다.
- 최종 버튼은 ‘현재 데이터를 이 백업으로 교체’. 쓰기에 실패하면 완료로 표시하지 않고 현재 데이터 복구 방안을 제공한다.
- 확인 기준: 빈 백업, 정상 백업, 예전 버전, 미지원 새 버전, 잘못된 파일, 취소, 저장 공간 부족, 새로고침 후 결과를 점검한다.

### 날짜 배정 안내

- 별도의 이동 알림 기능을 늘리는 대신, 빠른 입력의 목적지·날짜 미리보기로 사용자가 저장될 위치를 알 수 있게 한다.
- Inbox에서 직접 날짜를 지정하는 기존 기능은 유지한다.
